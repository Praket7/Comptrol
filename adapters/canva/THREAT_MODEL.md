# Threat model

The OAuth bearer token is taken only from `COMPTROL_CANVA_ACCESS_TOKEN` at request time; it is never written to disk, never logged, and every upstream error is redacted before it leaves the adapter, so the secret cannot leak through responses or audit payloads. Export download URLs are pre-signed and fetched without any `Authorization` header, and their bytes stream straight to files under `COMPTROL_CANVA_EXPORT_DIR` while responses carry only size plus sha256. Callers must grant least-privilege OAuth scopes (`design:meta:read` for reads, `design:content:read` for exports, editing scopes only when the App bridge mutation path is enabled).

The companion App bridge runs the Apps SDK Design Editing model inside a Canva iframe and is constrained as follows: it accepts `postMessage` traffic only from the origin allowlist (`https://www.canva.com`, plus loopback only when `COMPTROL_CANVA_BASE` points at a test stub), rejects any message from other origins without acting, never receives the bearer token (the iframe URL and message bodies carry only the exact design id plus the validated typed operation), applies only opaque element ids bound to that design id, and refuses any payload containing screen coordinates or replay scripts. Stale `expected_revision` values are refused before any bridge call, and every mutation must be confirmed by a design reread showing a new revision before reporting success.
