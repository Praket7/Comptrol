# Verification contract

Reads are verified from live Connect API responses: `design.list` returns bounded per-design summaries plus the upstream continuation token, `design.read` returns the exact bound id with edit/view URLs and revision, and `design.page.list` returns the live page range; each reports `verified=true` with a `canva_*_readback` marker. Every edit binds the exact design id plus its current revision, refuses stale `expected_revision` values without touching the design, and — once the companion App bridge passes production constraints — the bridge must reread the design and compare the new revision plus the affected element before reporting `verified=true`. Until then the bridge intents return `design_editing_app_required` with the validated operation echoed and change nothing, which is itself asserted. A bare upstream success is delivery evidence, not task completion. Exports verify the persisted artifacts on disk by `size_bytes` and `sha256` per file, and never move file bytes through the frame; with `COMPTROL_CANVA_EXPORT_DIR` unset the adapter returns job metadata only (`persisted=false`, `verified=false`).

Verify with: `python3.11 -m py_compile src/adapter.py`, a handshake frame through stdio expecting `comptrol.canva`, a `design.read` against a loopback stub via `COMPTROL_CANVA_BASE` asserting the bound id and revision, a `design.page.list` asserting the page count and continuation handling, a `design.text.update` with a stale `expected_revision` asserting a `stale_revision` refusal with no export or bridge call issued, a `design.text.update` with a fresh revision asserting `design_editing_app_required` with the typed echo and no coordinates, and a `design.export` asserting the on-disk bytes hash to the reported sha256 (plus a metadata-only run with the export dir unset asserting `persisted=false`).
